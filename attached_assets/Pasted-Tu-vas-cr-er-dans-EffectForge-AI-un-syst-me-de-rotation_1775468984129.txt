Tu vas créer dans EffectForge AI un système de rotation 
intelligente des clés API pour Gemini Flash, Cerebras 
et Serper. Ce système doit maximiser l'utilisation des 
quotas gratuits disponibles en évitant les cooldowns 
et les rate limits de chaque clé.

═══════════════════════════════════════════════════════
ARCHITECTURE DU SYSTÈME DE ROTATION
═══════════════════════════════════════════════════════

Créer server/services/api-key-rotator.ts

Ce module est le cerveau central de gestion 
de toutes les clés API tierces.
Il s'occupe de :
- Tracker l'état de chaque clé en temps réel
- Détecter automatiquement les rate limits
- Basculer vers la prochaine clé disponible
- Mémoriser les quotas utilisés par jour
- Alerter quand toutes les clés d'un service 
  sont épuisées

PARTIE 2 — STRUCTURE DE DONNÉES DU ROTATEUR
═══════════════════════════════════════════════════════

interface ApiKey {
  id: string                    // "gemini_1", "cerebras_3"...
  service: 'gemini' | 'cerebras' | 'serper'
  key: string                   // La clé API réelle
  status: 'active'              // Disponible maintenant
         | 'cooldown'           // En pause temporaire
         | 'exhausted'          // Quota journalier épuisé
         | 'error'              // Erreur irrécupérable
  usageToday: number            // Requêtes utilisées aujourd'hui
  dailyLimit: number            // Limite journalière estimée
  lastUsed: Date | null         // Dernière utilisation
  cooldownUntil: Date | null    // Fin du cooldown actuel
  cooldownCount: number         // Nombre de cooldowns aujourd'hui
  errorCount: number            // Erreurs consécutives
  successCount: number          // Succès total
  avgResponseTime: number       // Temps de réponse moyen (ms)
  lastError: string | null      // Dernière erreur reçue
}

interface KeyPool {
  gemini: ApiKey[]
  cerebras: ApiKey[]
  serper: ApiKey[]
}

Limites journalières estimées par service :
- Gemini Flash gratuit : ~1500 requêtes/jour/clé
- Cerebras gratuit : ~1000 requêtes/jour/clé  
- Serper gratuit : ~500 requêtes/mois/clé 
  (soit ~17/jour pour tenir le mois)

═══════════════════════════════════════════════════════
PARTIE 3 — LOGIQUE DE ROTATION INTELLIGENTE
═══════════════════════════════════════════════════════

La rotation suit une logique de priorité :

ALGORITHME DE SÉLECTION :

function selectBestKey(service: string): ApiKey {

  1. Filtrer les clés 'active' uniquement
  
  2. Parmi les clés actives, trier par priorité :
  
     PRIORITÉ 1 — La clé avec le moins 
     d'utilisations aujourd'hui
     (préserve les clés les moins utilisées 
     pour les tâches futures)
     
     PRIORITÉ 2 — La clé avec le meilleur 
     temps de réponse moyen
     (favorise les clés les plus rapides)
     
     PRIORITÉ 3 — La clé utilisée 
     il y a le plus longtemps
     (rotation naturelle pour éviter 
     la concentration sur une seule clé)
  
  3. Si aucune clé active :
     Vérifier les clés en 'cooldown'
     Sélectionner celle dont le cooldown 
     se termine le plus tôt
     Attendre sa disponibilité (max 30s)
     Si attente > 30s → retourner erreur
     "Toutes les clés sont en cooldown"
  
  4. Si toutes 'exhausted' :
     Retourner erreur "Quota journalier 
     épuisé pour [service]. 
     Réinitialisation dans [temps]."
}

DÉTECTION AUTOMATIQUE DES RATE LIMITS :

Quand une requête retourne une erreur,
analyser le code et le message :

Code 429 "Too Many Requests" :
→ status = 'cooldown'
→ cooldownUntil = maintenant + 60 secondes
→ Retry immédiat avec la prochaine clé

Code 429 avec header Retry-After :
→ status = 'cooldown'
→ cooldownUntil = maintenant + Retry-After
→ Retry immédiat avec la prochaine clé

Code 403 "Quota exceeded" :
→ status = 'exhausted'
→ Planifier réinitialisation à minuit UTC
→ Retry avec la prochaine clé disponible

Code 401 "Invalid API Key" :
→ status = 'error'
→ errorCount++
→ Logger l'incident
→ Retry avec la prochaine clé

Toute autre erreur :
→ errorCount++
→ Si errorCount >= 3 → status = 'error'
→ Retry avec la prochaine clé

SYSTÈME DE COOLDOWN PROGRESSIF :

Chaque fois qu'une clé déclenche un rate limit,
son cooldown augmente progressivement :

cooldownCount = 1 → cooldown 60 secondes
cooldownCount = 2 → cooldown 120 secondes
cooldownCount = 3 → cooldown 300 secondes
cooldownCount = 4+ → cooldown 600 secondes

Réinitialisation des cooldownCount à minuit.

RÉPARTITION SERPER SPÉCIALE :

Serper a 2500 scraps/mois pour 5 clés
= 500/mois/clé = ~17/jour/clé

Logique spéciale pour Serper :
- Ne jamais dépasser 15 requêtes/jour/clé
  (garde 2 de marge de sécurité)
- Distribuer uniformément sur les 5 clés
  (3 requêtes/clé avant rotation forcée)
- Alerter si consommation > 80% du quota mensuel

server/services/gemini-wrapper.ts

export async function callGemini(
  prompt: string,
  options: {
    temperature?: number
    maxTokens?: number
    isVision?: boolean
    imageBase64?: string
  }
): Promise<string> {

  const key = await rotator.selectBestKey('gemini')
  
  try {
    const startTime = Date.now()
    
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models/gemini-flash:generateContent?key=${key.key}`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          contents: [{
            parts: options.isVision 
              ? [
                  { text: prompt },
                  { 
                    inline_data: { 
                      mime_type: 'image/png',
                      data: options.imageBase64 
                    }
                  }
                ]
              : [{ text: prompt }]
          }],
          generationConfig: {
            temperature: options.temperature ?? 0.7,
            maxOutputTokens: options.maxTokens ?? 2000
          }
        })
      }
    )
    
    if (!response.ok) {
      await rotator.handleError(key, response.status, 
        await response.text())
      // Retry automatique avec nouvelle clé
      return callGemini(prompt, options)
    }
    
    const data = await response.json()
    const responseTime = Date.now() - startTime
    
    await rotator.recordSuccess(key, responseTime)
    
    return data.candidates[0].content.parts[0].text
    
  } catch (error) {
    await rotator.handleError(key, 500, error.message)
    return callGemini(prompt, options)
  }
}

server/services/cerebras-wrapper.ts

export async function callCerebras(
  prompt: string,
  options: {
    temperature?: number
    maxTokens?: number
    systemPrompt?: string
  }
): Promise<string> {

  const key = await rotator.selectBestKey('cerebras')
  
  try {
    const startTime = Date.now()
    
    const messages = []
    if (options.systemPrompt) {
      messages.push({ 
        role: 'system', 
        content: options.systemPrompt 
      })
    }
    messages.push({ role: 'user', content: prompt })
    
    const response = await fetch(
      'https://api.cerebras.ai/v1/chat/completions',
      {
        method: 'POST',
        headers: {
          'Authorization': `Bearer ${key.key}`,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({
          model: 'llama-3.3-70b',
          messages,
          max_tokens: options.maxTokens ?? 2000,
          temperature: options.temperature ?? 0.7
        })
      }
    )
    
    if (!response.ok) {
      await rotator.handleError(key, response.status,
        await response.text())
      return callCerebras(prompt, options)
    }
    
    const data = await response.json()
    const responseTime = Date.now() - startTime
    
    await rotator.recordSuccess(key, responseTime)
    
    return data.choices[0].message.content
    
  } catch (error) {
    await rotator.handleError(key, 500, error.message)
    return callCerebras(prompt, options)
  }
}

server/services/serper-wrapper.ts

export async function callSerper(
  query: string,
  options: {
    type?: 'search' | 'places' | 'maps'
    num?: number
  }
): Promise<any> {

  const key = await rotator.selectBestKey('serper')
  
  // Vérification quota mensuel Serper
  const monthlyUsage = await rotator.getMonthlyUsage('serper')
  if (monthlyUsage >= 2400) {
    throw new Error('Quota mensuel Serper presque épuisé. 
                     100 requêtes de réserve conservées.')
  }
  
  try {
    const startTime = Date.now()
    
    const response = await fetch(
      'https://google.serper.dev/search',
      {
        method: 'POST',
        headers: {
          'X-API-KEY': key.key,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({
          q: query,
          num: options.num ?? 5,
          gl: 'fr',
          hl: 'fr'
        })
      }
    )
    
    if (!response.ok) {
      await rotator.handleError(key, response.status,
        await response.text())
      return callSerper(query, options)
    }
    
    const data = await response.json()
    const responseTime = Date.now() - startTime
    
    await rotator.recordSuccess(key, responseTime)
    await rotator.recordMonthlyUsage('serper')
    
    return data
    
  } catch (error) {
    await rotator.handleError(key, 500, error.message)
    return callSerper(query, options)
  }
}

PARTIE 5 — PERSISTANCE DE L'ÉTAT
═══════════════════════════════════════════════════════

L'état des clés doit persister entre les redémarrages
du serveur Replit pour ne pas perdre le tracking 
des quotas utilisés.

Créer server/services/key-state-persistence.ts

Sauvegarder l'état toutes les 60 secondes 
dans un fichier JSON local :
data/api-keys-state.json

Structure sauvegardée :
{
  "lastSaved": "ISO date",
  "keys": {
    "gemini_1": {
      "usageToday": 47,
      "status": "active",
      "cooldownUntil": null,
      "cooldownCount": 0,
      "errorCount": 0,
      "successCount": 234,
      "avgResponseTime": 1240
    },
    ...
  },
  "monthlyUsage": {
    "serper": {
      "2026-04": 127
    }
  }
}

Réinitialisation automatique à minuit UTC :
- usageToday → 0 pour toutes les clés
- status 'exhausted' → 'active'
- cooldownCount → 0
- Garder successCount et avgResponseTime

═══════════════════════════════════════════════════════
PARTIE 7 — RETRY ET FALLBACK FINAL
═══════════════════════════════════════════════════════

Si après rotation de toutes les clés d'un service
aucune n'est disponible, le système applique 
cette stratégie de fallback :

FALLBACK GEMINI → Claude (Replit)
Si toutes les clés Gemini sont épuisées,
basculer automatiquement vers Claude via 
l'API Anthropic déjà intégrée dans Replit.
Logger la substitution pour suivi.

FALLBACK CEREBRAS → Gemini
Si toutes les clés Cerebras sont épuisées,
utiliser Gemini Flash pour les tâches 
de génération de contenu texte.

FALLBACK SERPER → Cache local
Si toutes les clés Serper sont épuisées,
retourner les données en cache si disponibles
(TTL 24h pour les données GMB).
Si pas de cache → message utilisateur :
"Scraping temporairement indisponible.
 Remplissez le formulaire manuellement."
